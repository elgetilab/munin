User Guide

Chat

The chat interface is the main way to interact with Munin. Type a question, and the assistant will respond with a streamed answer. Your conversations are saved automatically and accessible from the sidebar.

Choosing a persona

Use the persona selector (bottom right of the input) to switch between three specialized assistants:

Meitner [Chat]

General-purpose assistant. Use for writing, web lookups, brainstorming, email drafts, and everyday questions.

Turing [Code]

Code assistant. Use for Python scripts, debugging, data analysis, SLURM jobs, and technical questions.

Curie [Research]

Research assistant. Use for literature search, paper analysis, citation exploration, and finding related work.

You can switch personas at any time, even mid-conversation. All three use the same underlying model with different system prompts and tool access.

Extended thinking

The model reasons through your question step by step before answering. This thinking process is shown in a collapsible section at the top of each response. You can expand it if you're curious, or just ignore it.

Paper Search

Paper Search is a fast, interactive search tool for finding scientific papers in our database.

  • Type a topic, author name, or DOI into the search bar.
  • Results are ranked by semantic similarity, not just keywords, so you'll find conceptually related work even if the exact terms don't match.
  • Click a result to see its abstract, metadata, and a link to the full PDF (when available).
  • Filter by author or year range to narrow results.

Deep Research

Deep Research is for complex questions that need thorough investigation. Unlike chat (which responds in seconds), deep research jobs run for 5 to 20 minutes and produce structured reports.

  • Submit a research question (e.g. "What are the current approaches to studying lipid raft formation in cell membranes?").
  • The system searches multiple sources, reads papers, and synthesizes a report with citations.
  • When the job finishes, download the result as PDF or Markdown.

Use deep research when you need a comprehensive overview of a topic. For quick lookups or specific paper searches, chat or paper search are faster.

Knowledge Browser

The Knowledge Browser gives you a visual overview of everything in the internal paper database — organized by research group, topic cluster, and contributor.

Overview page

  • Stats: See total paper count, number of topics, research groups, and contributors at a glance.
  • Embedding map: A 2D visualization of all papers projected into a scatter plot. Papers are colored by topic cluster. Hover to see titles, click to browse that topic. Use the cluster chips below to filter the map to a single topic.
  • Research groups: Cards showing each group's contribution. Click "Browse papers" to see their papers or "Discuss in chat" to start a conversation scoped to that group.
  • Topics: Searchable list of all topic clusters. Click any topic to browse its papers.

Browsing papers

When you click into a group, topic, or contributor, you get a paginated list of papers with:

  • Title, year, journal, and authors
  • Topic label and contributor attribution
  • PDF download link (when available)
  • Sorting by newest, oldest, or recently added

Tag filters in chat

You can scope chat conversations to specific knowledge subsets using #tag filters:

  • Type # in the chat input to open the tag autocomplete.
  • Select a research group, topic, or contributor to add it as a filter chip.
  • Multiple tags are combined (AND logic) — e.g., a group + topic restricts to papers in that group about that topic.
  • Click "Discuss in chat" on any Knowledge Browser page to jump to chat with that tag pre-filled.

Tags tell the assistant which part of the knowledge base to search. Without tags, it searches everything.

Knowledge Sources

When you ask a question, the assistants can draw from three sources:

Web Search

All personas can search the web for current information: news, documentation, tutorials, or anything beyond their training data.

Academic Databases

The assistants query Semantic Scholar and OpenAlex to find published papers, citations, and author information across all scientific fields.

Internal Paper Database

Our own curated collection of papers, searchable by meaning (not just keywords). This is the same database that powers Paper Search.

The assistant will indicate which source a piece of information came from. If you're unsure whether an answer is grounded in a source or generated from the model's training, just ask.

Contributing to the Knowledge Base

You can grow the internal paper database by uploading PDFs on the Upload page.

  • Drag and drop PDFs (or click to browse). You can upload up to 1,000 files at once.
  • Uploads are resumable: if your connection drops, they pick up where they left off.
  • Uploaded papers are automatically indexed (title, abstract, metadata extracted) and become searchable for all users.
  • This is different from attaching a file in chat. Files attached in chat are only visible in that conversation. Files uploaded via the Upload page go into the shared database permanently.

API Access

Munin provides an API at https://api.muninai.org/v1. The API supports two modes: a raw mode that is fully OpenAI-compatible, and a persona mode that uses Munin's research assistants with custom SSE streaming.

Getting an API key

Open Chat → click your name (bottom of the sidebar) → Settings → scroll to API Keys. Create a key — it starts with sk-munin-. Copy it immediately; it won't be shown again.

Authentication

Pass your key as a Bearer token in the Authorization header: 

Authorization: Bearer sk-munin-...

Available endpoints

POST /v1/chat/completions

Send a chat message. Accepts the same JSON body as the OpenAI API (model + messages array). Response format depends on the mode — see below.

Two modes

The response format depends on whether you include a persona field in your request:

Raw mode (default, OpenAI-compatible)

Omit the persona field or set it to "raw". The model runs without any system prompt — your messages are passed directly to the LLM. Returns standard OpenAI JSON.

This mode works with the OpenAI Python SDK, Cursor, aider, and any OpenAI-compatible client.

Persona mode (Munin assistants)

Set "persona" to "chat" (Meitner), "code" (Turing), or "research" (Curie). The assistant's system prompt is injected and tools (web search, paper search, citations) are available. Returns a custom SSE stream.

Standard OpenAI SDKs will not parse the persona SSE response correctly — use a raw HTTP client or SSE library instead.

Raw mode — OpenAI-compatible response

When using raw mode, the response is standard OpenAI JSON:

{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "qwen3.6-35b-a3b",
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": "Hello!",
      "reasoning": "The user wants me to say hello..."
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 15,
    "completion_tokens": 42,
    "total_tokens": 57
  }
}

The reasoning field contains the model's chain-of-thought (always-on). The model is Qwen3.6-35B-A3B, a Mixture-of-Experts architecture with 3B active parameters per forward pass.

Persona mode — custom SSE response

When using persona mode, the response is a Server-Sent Events stream with these event types:

Event types

conversation — Conversation metadata (ID, title). Sent at the start and when the title is generated.

thinking — Chain-of-thought reasoning tokens. Can be ignored if you only want the final answer.

token — Response content tokens. Concatenate these to build the assistant's reply.

tool_call — Tool invocation (web search, paper search, etc.).

done — Final event with usage statistics and finish reason.

Rate limits

  • 1 concurrent request
  • 10 requests per minute
  • 2,000,000 tokens per month (API usage only — browser chat does not count)

When a limit is hit you'll receive a 429 response. Check your current usage in chat Settings.

Python example — raw mode (OpenAI SDK)

from openai import OpenAI

client = OpenAI(
    api_key="sk-munin-...",
    base_url="https://api.muninai.org/v1",
)

response = client.chat.completions.create(
    model="qwen3.6-35b-a3b",
    messages=[{"role": "user", "content": "Hello!"}],
)

print(response.choices[0].message.content)
print(f"Tokens used: {response.usage.total_tokens}")

Python example — persona mode (SSE)

import httpx, json

API_KEY = "sk-munin-..."
BASE_URL = "https://api.muninai.org/v1"

with httpx.stream(
    "POST",
    f"{BASE_URL}/chat/completions",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "model": "qwen3.6-35b-a3b",
        "persona": "research",
        "messages": [{"role": "user", "content": "Find papers on lipid rafts"}],
    },
    timeout=120,
) as response:
    reply = ""
    event = ""
    for line in response.iter_lines():
        if line.startswith("event: "):
            event = line[7:]
        elif line.startswith("data: "):
            data = json.loads(line[6:])
            if event == "token":
                reply += data["content"]
            elif event == "done":
                print(f"Tokens used: {data['usage']['total_tokens']}")

    print(reply)

curl example — raw mode

curl https://api.muninai.org/v1/chat/completions \
  -H "Authorization: Bearer sk-munin-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.6-35b-a3b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

# Returns standard OpenAI JSON response

curl example — persona mode

curl -N https://api.muninai.org/v1/chat/completions \
  -H "Authorization: Bearer sk-munin-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.6-35b-a3b",
    "persona": "research",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

# Returns SSE stream with event/data lines

Using Munin with opencode

opencode is an open-source terminal coding agent that supports any OpenAI-compatible API. You can point it at Munin and use Turing (the code persona) as your local coding assistant. The setup is a single config file plus an environment variable.

1. Install opencode

# macOS / Linux
curl -fsSL https://opencode.ai/install | bash

# Or via npm
npm install -g opencode-ai

2. Create an API key

Open Chat → click your name → Settings → API Keys. Create a key (it starts with sk-munin-) and copy it — it won't be shown again.

3. Export your key

Add this to your shell profile (~/.bashrc, ~/.zshrc, etc.) so opencode can pick it up:

export MUNIN_API_KEY="sk-munin-..."

4. Configure the provider

Create ~/.config/opencode/opencode.json for a global setup, or drop an opencode.json in any project root for a per-project setup:

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "munin": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Munin",
      "options": {
        "baseURL": "https://api.muninai.org/v1",
        "apiKey": "{env:MUNIN_API_KEY}"
      },
      "models": {
        "qwen3.6-35b-a3b": {
          "name": "Qwen 3.5 35B"
        }
      }
    }
  }
}

Notes:

  • opencode uses standard OpenAI chat completions, so requests automatically hit Munin's raw mode — the underlying model with no Munin persona, no system prompt, and no Munin tools. Opencode injects its own coding agent prompt.
  • Munin's API rate limits apply: 1 concurrent request, 10 requests/minute, 2M tokens/month. Opencode can burn tokens fast on large repos — keep an eye on usage in chat Settings.

5. Run it

cd your-project
opencode

On first launch, pick the Munin provider and the qwen3.6-35b-a3b model. You can switch model/provider any time inside the TUI with /model.

Tips

  • Be specific. "Find papers on cholesterol-lipid interactions in DPPC membranes" works better than "find papers on lipids".
  • Use the right tool. Quick factual question? Chat. Need a specific paper? Paper Search. Need a full literature overview? Deep Research.
  • Switch personas freely. Start with Curie to find papers, switch to Turing to implement something, use Meitner to write it up.
  • Upload your papers. The more papers in the database, the better the search results for everyone.
