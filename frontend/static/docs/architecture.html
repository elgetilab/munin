Routing Profile Comparison

Munin is one user-facing assistant. An up-front router picks one of three internal profiles per turn from the query (slash commands /chat, /code, /research force a profile). Each profile shares the same Munin base prompt and differs only in its task guidance, sampling, and surfaced tools.

Profile Purpose Thinking Mode Tools Available
chat General-purpose chat, writing, web search, quick lookups Enabled Paper Search, Web Search, Date/Time
code Code assistant, scientific Python, debugging, code review Enabled Web Search, Date/Time
research Research assistant, literature search, paper analysis, citations Enabled Paper Search, Citations, Academic Search (Semantic Scholar, OpenAlex), Web Search

All profiles use the same underlying model: Qwen3.8-27B (dense 27B, hybrid Gated DeltaNet + attention, thinking on by default).

Workflow: just ask, and Munin routes to research for discovery and analysis, code for implementation, and chat for general tasks and writing.

RAG (Retrieval-Augmented Generation) Flow

When you ask a question with RAG enabled, here's what happens:

1 Query Received

The chat UI receives your question and routes it to the API gateway.

2 Parallel Retrieval

The retrieval service queries all selected sources simultaneously (papers, web).

3 Semantic Search

Your query is embedded using SPECTER (papers) and compared against stored vectors in Qdrant.

4 Context Assembly

Top matching documents are ranked and assembled into context for the LLM, with source attribution.

5 LLM Generation

The LLM receives your question + retrieved context and generates a grounded response with citations.
