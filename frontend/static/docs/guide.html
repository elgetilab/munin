User Guide

How to use Chat, Paper Search, the Knowledge Browser and Upload, and how to reach Munin from your own code.

Chat

The chat interface is the main way to interact with Munin. Type a question, and the assistant will respond with a streamed answer. Your conversations are saved automatically and accessible from the sidebar.

How Munin routes

You don't pick a model. Munin automatically routes each question to the right mode. When you want to force a specific mode for one message, start it with a slash command:

Chat /chat
General-purpose. Writing, web lookups, brainstorming, email drafts, and everyday questions.
Code /code
Code assistant. Python scripts, debugging, data analysis, SLURM jobs, and technical questions.
Research /research
Research assistant. Literature search, paper analysis, citation exploration, and finding related work.

Most of the time you can just ask, and Munin picks the right mode per turn. The slash commands are there for when you want to steer it explicitly. All modes use the same underlying model with different guidance and tool access.

Extended thinking

The model reasons through your question step by step before answering. This thinking process is shown in a collapsible section at the top of each response. You can expand it if you're curious, or just ignore it.

Paper Search

Paper Search is a fast, interactive search tool for finding scientific papers in our database.

  • Type a topic or DOI into the search bar.
  • To list someone's papers, type their name in the Author filter and leave the search bar empty.
  • Results are ranked by meaning and citations, not just keywords, so you'll find conceptually related work even if the exact terms don't match.
  • Each result shows its abstract, metadata, and a PDF download (when available). The title opens the paper at doi.org.
  • Filter by author or year range to narrow results. A year range needs a topic or an author to narrow.

Deep Research

Give Munin a question and it works through it in the background: it plans sub-questions, searches the paper corpus, open-access literature and the web, reads the sources, and delivers a cited report in your conversation.

  1. In the Chat composer, open the + menu.
  2. Choose Deep Research, so that it shows On.
  3. Send your question, without attachments.

It turns itself off after each report, and isn't available in temporary chats.

Knowledge Browser

The Knowledge Browser gives you a visual overview of everything in the internal paper database, organized by research group, topic cluster, and contributor.

Overview page

Stats
See total paper count, number of topics, research groups, and contributors at a glance.
Embedding map
A 2D visualization of all papers projected into a scatter plot. Papers are coloured by topic cluster. Hover to see titles, click to browse that topic. Use the cluster chips below to filter the map to a single topic.
Research groups
Cards showing each group's contribution. Click "Browse papers" to see their papers or "Discuss in chat" to start a conversation scoped to that group.
Topics
Searchable list of all topic clusters. Click any topic to browse its papers.

Browsing papers

When you click into a group, topic, or contributor, you get a paginated list of papers with:

  • Title, year, journal, and authors
  • Topic label and contributor attribution
  • PDF download link (when available)
  • Sorting by newest, oldest, or recently added

Tag filters in chat

You can scope chat conversations to specific knowledge subsets using #tag filters:

  • Type # in the chat input to open the tag autocomplete.
  • Select a research group, topic, or contributor to add it as a filter chip.
  • Multiple tags are combined (AND logic): a group + topic restricts to papers in that group about that topic.
  • Click "Discuss in chat" on any Knowledge Browser page to jump to chat with that tag pre-filled.

Tags tell the assistant which part of the knowledge base to search. Without tags, it searches everything.

Knowledge Sources

When you ask a question, Munin can draw from three sources:

Web Search
Munin can search the web for current information: news, documentation, tutorials, or anything beyond their training data.
Academic Databases
Munin queries Semantic Scholar and OpenAlex to find published papers, citations, and author information across all scientific fields.
Internal Paper Database
Our own curated collection of papers, searchable by meaning (not just keywords). This is the same database that powers Paper Search.

Munin will indicate which source a piece of information came from. If you're unsure whether an answer is grounded in a source or generated from the model's training, just ask.

Contributing to the Knowledge Base

Research group leaders can grow the internal paper database by uploading PDFs on the Upload page. If you aren't a group leader, ask yours or contact support.

  • Drag and drop PDFs (or click to browse). You can upload up to 1,000 files at once.
  • Uploads are resumable: if your connection drops, they pick up where they left off.
  • Uploaded papers are automatically indexed (title, abstract, metadata extracted) and become searchable for all users.
  • This is different from attaching a file in chat. Files attached in chat are only visible in that conversation. Files uploaded via the Upload page go into the shared database permanently.

API Access

Munin provides an API at {{env "MUNIN_URL_API"}}. The API supports two modes: a raw mode that is fully OpenAI-compatible, and a persona mode that uses Munin's research assistants with custom SSE streaming.

Getting an API key

Open Chat, click your name (bottom of the sidebar), then Settings, and scroll to API Keys. Create a key; it starts with sk-munin-. Copy it immediately; it won't be shown again.

Authentication

Pass your key as a Bearer token in the Authorization header: 

Authorization: Bearer sk-munin-...

Available endpoints

POST /v1/chat/completions
Send a chat message. Accepts the same JSON body as the OpenAI API (model + messages array). Response format depends on the mode; see below.
GET /v1/models
List available models in OpenAI format. Clients that probe this on connect (Positron, Cursor, the OpenAI SDK) use it to validate the provider and populate the model picker. Returns a single model, qwen3.8-27b.

Two modes

The response format depends on whether you include a persona field in your request:

Raw mode (default, OpenAI-compatible)

Omit the persona field or set it to "raw". The model runs without any system prompt: your messages are passed directly to the LLM. Returns standard OpenAI JSON.

This mode works with the OpenAI Python SDK, Cursor, aider, and any OpenAI-compatible client.

Munin mode (full pipeline)

Omit "persona" (or set it to "munin") to let Munin auto-route. To force a mode, set "persona" to "chat", "code", or "research". The system prompt is injected and tools (web search, paper search, citations) are available. Returns a custom SSE stream.

Standard OpenAI SDKs will not parse the persona SSE response correctly; use a raw HTTP client or SSE library instead.

Raw mode: OpenAI-compatible response

When using raw mode, the response is standard OpenAI JSON:

{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "qwen3.8-27b",
  "choices": [{
    "index": 0,
    "message": {
      "role": "assistant",
      "content": "Hello!",
      "reasoning": "The user wants me to say hello..."
    },
    "finish_reason": "stop"
  }],
  "usage": {
    "prompt_tokens": 15,
    "completion_tokens": 42,
    "total_tokens": 57
  }
}

The reasoning field contains the model's chain-of-thought (always-on). The model is Qwen3.8-27B, a dense 27B model with a hybrid Gated DeltaNet + attention architecture.

Munin mode: custom SSE response

When using persona mode, the response is a Server-Sent Events stream with these event types:

EventContents
conversationConversation metadata (ID, title). Sent at the start and when the title is generated.
thinkingChain-of-thought reasoning tokens. Can be ignored if you only want the final answer.
tokenResponse content tokens. Concatenate these to build the assistant's reply.
tool_callTool invocation (web search, paper search, etc.).
doneFinal event with usage statistics and finish reason.

Quota

  • 100,000,000 tokens per month (API usage only; browser chat does not count)

There is no requests-per-minute limit and no cap on concurrent requests: send as many as you like and the server queues them. The monthly token quota is the only limit. When it is exhausted you'll receive a 429 response. Check your current usage in chat Settings.

Context window

The model has a 64k token context window (65,536 tokens, shared between your prompt and the generated response). If a request's prompt plus its max_tokens would exceed that, Munin automatically reduces max_tokens to fit and retries, so long sessions keep working. If the prompt alone exceeds the window you'll get a clear 400 error ("maximum context length is 65536 tokens..."). Trim the conversation or start a new chat.

Tip: some clients (e.g. Positron) default max_tokens to a large value like 16384, which reserves a quarter of the window for output and makes long sessions fail sooner. Lowering max_tokens (e.g. 2048–4096) leaves much more room for conversation history.

Python example: raw mode (OpenAI SDK)

from openai import OpenAI

client = OpenAI(
    api_key="sk-munin-...",
    base_url="{{env "MUNIN_URL_API"}}",
)

response = client.chat.completions.create(
    model="qwen3.8-27b",
    messages=[{"role": "user", "content": "Hello!"}],
)

print(response.choices[0].message.content)
print(f"Tokens used: {response.usage.total_tokens}")

Python example: Munin mode (SSE)

import httpx, json

API_KEY = "sk-munin-..."
BASE_URL = "{{env "MUNIN_URL_API"}}"

with httpx.stream(
    "POST",
    f"{BASE_URL}/chat/completions",
    headers={"Authorization": f"Bearer {API_KEY}"},
    json={
        "model": "qwen3.8-27b",
        "persona": "research",
        "messages": [{"role": "user", "content": "Find papers on lipid rafts"}],
    },
    timeout=120,
) as response:
    reply = ""
    event = ""
    for line in response.iter_lines():
        if line.startswith("event: "):
            event = line[7:]
        elif line.startswith("data: "):
            data = json.loads(line[6:])
            if event == "token":
                reply += data["content"]
            elif event == "done":
                print(f"Tokens used: {data['usage']['total_tokens']}")

    print(reply)

curl example: raw mode

curl {{env "MUNIN_URL_API"}}/chat/completions \
  -H "Authorization: Bearer sk-munin-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-27b",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

# Returns standard OpenAI JSON response

curl example: Munin mode

curl -N {{env "MUNIN_URL_API"}}/chat/completions \
  -H "Authorization: Bearer sk-munin-..." \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.8-27b",
    "persona": "research",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'

# Returns SSE stream with event/data lines

Using Munin with opencode

opencode is an open-source terminal coding agent that supports any OpenAI-compatible API. You can point it at Munin as your local coding assistant; set persona to code to force the code mode, or leave it to auto-route. The setup is a single config file.

1. Install opencode

# macOS / Linux
curl -fsSL https://opencode.ai/install | bash

# Or via npm
npm install -g opencode-ai

2. Create an API key

Open Chat, click your name, then Settings and API Keys. Create a key (it starts with sk-munin-) and copy it; it won't be shown again.

3. Verify your key

Before wiring up opencode, confirm the key works. Paste it into a quick curl against the model list: 

# should return a JSON list containing qwen3.8-27b
curl -s -H "Authorization: Bearer sk-munin-..." {{env "MUNIN_URL_API"}}/models

If the model list comes back, the key is good and you'll paste it straight into opencode.json in the next step. A 401 means the key is wrong or expired; regenerate it before continuing, otherwise opencode will not see the model.

4. Configure the provider

Create ~/.config/opencode/opencode.json for a global setup, or drop an opencode.json in any project root for a per-project setup:

{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "munin": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Munin",
      "options": {
        "baseURL": "{{env "MUNIN_URL_API"}}",
        "apiKey": "APIKEYHERE"
      },
      "models": {
        "qwen3.8-27b": {
          "name": "Qwen 3.8 27B",
          "limit": {
            "context": 65536,
            "output": 16384
          }
        }
      }
    }
  }
}

Notes:

  • Replace APIKEYHERE with the sk-munin- key from step 2. opencode reads the key literally, so paste it in directly. If you keep opencode.json in a project, don't commit it: the key grants access to your quota.
  • The limit block matches the current deployment: a 65,536-token context window with up to 16,384 tokens of output per turn. opencode uses these to manage its context and compaction.
  • opencode uses standard OpenAI chat completions, so requests automatically hit Munin's raw mode: the underlying model with no Munin persona, no system prompt, and no Munin tools. Opencode injects its own coding agent prompt.
  • Munin's only API limit is 100M tokens/month, with no request-rate or concurrency cap. Opencode can burn tokens fast on large repos, so keep an eye on usage in chat Settings.

5. Run it

cd your-project
opencode

On first launch, pick the Munin provider and the qwen3.8-27b model. You can switch model/provider any time inside the TUI with /model.

Tips

  • Be specific. "Find papers on cholesterol-lipid interactions in DPPC membranes" works better than "find papers on lipids".
  • Use the right tool. Quick factual question or a full literature overview? Chat. Need a specific paper? Paper Search.
  • Steer with slash commands. Munin routes automatically, or start a message with /research to find papers, /code to implement something, or /chat to write it up.
  • Get your papers added. Your group leader can upload them. The more papers in the database, the better the search results for everyone.
